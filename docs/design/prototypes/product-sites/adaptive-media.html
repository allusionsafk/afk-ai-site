Windows playback / active development

Playback that understands the path, not just the file.

DemiMedia is a Windows media player built around reference-first playback, explicit enhancement, and a simple rule: requested settings and observed runtime state are not the same thing.

In development

Playback path / evidence travels with the decision

01Source

Container, codec, HDR/Dolby Vision profile, audio, timing.

02Decode

03Render

Reference by default; scaling, cleanup, RTX HDR/VSR and motion remain explicit choices.

04Display

Observe presentation state and fall back when the preferred path does not hold.

Runtime truth / 004 states

Make the playback decision inspectable.

Requested
What the user asked for: renderer, enhancement, motion, HDR, audio path.
Planned
What the application selected after looking at source and machine evidence.
Observed
What the decoder, renderer and presentation path actually reported at runtime.
Fallback
What changed when the preferred path failed, degraded, or could not be proven.

Measured boundary

Strong claims stop where the evidence stops.

Reference first

Enhancement is opt-in. Decoded PCM remains the safe audio baseline.

Dolby Vision stays literal

Supported Profile 7 → 8.1 conversion is separate from any native-playback claim unless the exact build proves it.

Hardware chains vary

HDR switching, bitstream/Atmos, decode, and renderer behavior depend on driver/display/receiver paths.

Release authority matters

The engineering repository is in active development; historical shared-repository prereleases are not silently presented as current standalone releases.
